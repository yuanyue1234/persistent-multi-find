# 高亮 · 素材绑定助手 1.13.0

## 1.13.0 当前规则

- 替换栏留空即删除匹配文字，仍先预览再确认。
- 左侧双向箭头切换到荧光笔图标后仅高亮，单项与全部替换均跳过；再次展开恢复原替换内容。
- [] 只添加一层当前前后缀，已有相同包裹时不重复添加。
- 词条按宿主实际宽度排列，普通弹窗与320px侧栏均可显示右侧操作。图标统一为拖动点阵、荧光笔、替换箭头、括号和设置滑杆；排除、替换、删除保留文字。

## 1.11.0 新增操作

- **独立窗口**：点击右上角“↗”，再拖动系统标题栏移动窗口，也可以调整窗口大小。固定关联打开时的网页，不会误操作插件窗口自身。
- **侧边栏**：点击右上角侧栏图标，在浏览器侧边栏打开。不支持该接口的浏览器会禁用此入口，可改用独立窗口。
- **划词快速添加**：在网页左键拖选文字，松开后出现小型添加图标；点击才会添加到当前方案。仅选中文字不会保存或替换。完整素材名唯一匹配时自动绑定对应图片。
- **选区替换**：网页有文字选区时，单项和批量替换只处理选区内完整匹配；没有选区时沿用当前剧本范围。预览中会显示范围，顶部素材说明与已有引用仍受保护。
- **空替换删除**：“替换为”留空即删除；仅高亮请关闭替换栏。
- **明确删除文字**：点击词条“排”进入词条设置，勾选“删除匹配文字”，点击“保存设置”。该词条会显示“删文”，仍需预览确认。右侧“×”只删除规则，不删除网页文字。
- **方案栏导航**：左右箭头滚动方案；双击左箭头回到第一个，双击右箭头到最后。鼠标放在方案栏上滚轮可横向滚动。
- **词条排序**：拖动每条左侧的点状把手上下移动，顺序自动保存；聚焦把手后也可按 Alt＋↑ / ↓。
- **统一界面**：颜色改为圆形色点；导入、素材、设置和预览面板都有关闭按钮，也可按 Esc 关闭；窄侧栏自动采用双行词条。

删除规则的文本导入 / 导出格式：

```text
需要删除的文字 - | {{删除}}
只高亮不替换的文字 - | {{仅高亮}}
```

`{{删除}}` 为兼容保留指令；普通空值同样表示删除。`{{仅高亮}}` 前缀保留只高亮模式及后面的替换内容。

更新：覆盖原目录后，在扩展管理页重新加载；先保存工作台内容，再刷新网页。不要卸载，以保留方案。本版新增 sidePanel 权限；原生独立窗口及侧栏尚未在安装后的扩展中实测。

1.10.0 新增：读取提示词顶部、“生成段”标题之前的图片说明，建立“素材名称 → 当前图片标签”映射。不读取私有接口、不猜素材 ID，不自动选择服装或伤势版本。

## 新版最快用法

1. 在平台左侧选好素材，等待右侧顶部出现 `@图片1 是 凯尔-9` 等说明。
2. 打开插件，选择方案，点击“读取素材”。插件会读取当前提示词第一个“生成段”标题之前的图片标签，不读取下方剧本中的引用，不将音频当图片。
3. 检查对应表：左侧是剧本原词，右侧是图片素材。默认填完整素材名 `凯尔-9`；若剧本写的是 `凯尔`，把左侧改为 `凯尔`。不要处理的行清空原词。
4. 点击“保存绑定”，再点“预览全部替换”。确认范围和数量后执行。只替换“生成段”及下方正文，不修改顶部说明和左侧素材。
5. 在平台预览提示词检查引用，再保存。出错先用“恢复上次”，不要先刷新。

只绑定一个素材时：复制 `凯尔-9` 到插件顶部关键词框，点击“添加”。当前顶部有同名且唯一的图片时自动绑定，不需要素材 ID；未找到时只建立普通高亮词条，不会猜图片。替换栏留空会删除文字；只高亮时请关闭替换栏。

添加或移除左侧素材后，重新打开“读取素材”或点击“重新读取”获取最新列表；保存绑定和预览也会重新核对当前素材。不会在后台擅自修改规则或正文。同一原词只能选择一个版本；不同分镜状态请使用不同方案。

### 自动绑定的导入 / 导出格式

```text
凯尔-9 - | {{图片:凯尔-9}}
凯尔 - | {{图片:凯尔-9}}
```

上述两行是两种写法的示例，按剧本文字选用即可。`{{图片:名称}}` 是插件内部绑定语法，不会原样写进剧本；执行时从当前分镜顶部解析并复用已有图片标签。原有 `[@名称#ID]` 格式仍受支持。

### 自动读取的边界

- 素材名相同但对应多个不同标签时，阻止自动绑定；可在平台改名区分，或展开“手动粘贴完整引用 / 复用旧引用”。
- 已保存的素材在当前分镜中被移除、找不到“生成段”标题、只有普通 `@图片1` 文字而无可复用标签时，会提示原因，不编造引用。
- 自动读取支持现有 `.mention-chip`、`data-mention`、不可编辑标签，以及顶部完整原始引用；若平台使用其他结构，需要继续适配。
- 已有引用不重复替换，切换素材版本不会直接修改正文里已经绑定的标签。
- 已通过本地 DOM 测试及模拟浏览器流程。尚未在真实工作台验证插入标签后保存、刷新与生成是否被平台完整识别；首次请在可丢弃分镜试用。本插件不代点保存或生成。

1.9.1 修复：弹窗打开时可能被压成一条。根文档使用独立的 520px 高度，只有内部布局适应可用窗口，避免根高度依赖初始视口。

由你决定使用哪个素材版本；插件记住“提示词原词 → 完整素材引用”，减少反复输入规则和逐个 @ 的操作。不会按名字自动选择服装、伤势等素材状态。

## 简单使用教程：按这 6 步操作

### 1. 先选好素材

在平台左侧添加本分镜需要的素材。例如塞拉用“腿部包扎”还是“腿部受伤”，仍由你判断。

### 2. 新建方案

打开插件，点击顶部“＋”，创建方案，例如“第35集·腿部包扎”。

- 点击方案名：切换方案。
- 双击方案名：改名。
- 点击“⧉”：复制当前方案，下一集可以接着改。

### 3. 添加素材绑定

点击“读取素材”，优先使用顶部读取结果；如果需要手动绑定，展开“手动粘贴完整引用 / 复用旧引用”，粘贴完整引用，例如：

```text
[@罗温-作战服05#2100561479451070464]
```

在对应的“原词”中填写 `罗温`，点击“保存绑定”。意思是：把提示词中的“罗温”替换成这个素材引用。此时只保存规则，还没有替换正文。插件不替你添加素材或猜测素材 ID。

### 4. 设置不需要替换的文字

例如要匹配“祭坛”，但不动“悬崖祭坛”：点击该条规则右侧的“排”，输入 `悬崖祭坛`，点击“保存设置”。多个排除词，每行写一个。

点击词条旁的色块可以修改高亮颜色，颜色会自动保存。

### 5. 预览并替换

打开要处理的分镜，点击插件底部“预览全部替换”。核对替换范围、规则和命中数量，没问题后点击“确认替换”。完成后会显示替换成功提示和各规则的替换次数。

已有素材引用会跳过，不会重复套入。若预览显示“删除文字”，请确认是否真的要删除；不需要执行的规则先取消勾选。

### 6. 检查结果，必要时恢复

在平台点击“预览提示词”，确认引用正确后再保存。插件不代点保存或生成，但平台自身可能自动保存。

替换错了，点击插件“恢复上次”。请在刷新页面或继续修改正文前恢复；刷新会清空恢复记录，后续编辑也可能导致恢复被拒绝。

### 多条规则：用批量导入更快

点击“导入 / 导出”，按每行一条填写：

```text
罗温 - | [@罗温-作战服05#2100561479451070464]
祭坛 -悬崖祭坛 | 神坛
```

然后点击“导入 / 更新”。

- `|` 左侧是匹配词及排除项，右侧是替换内容。
- 没有排除项，也可以保留空的 `-`。
- 普通名称不用勾选“按正则表达式导入”。
- “复制导出”可以复制当前方案的文本规则。

最常用的流程：选素材 → 复制上一套方案 → 修改有变化的绑定 → 预览替换 → 检查保存。

## 素材绑定：详细说明

1. 在平台选好素材，取得其完整引用，例如 `[@罗温-作战服05#2100561479451070464]`。素材应已添加到当前分镜左栏；插件不替你添加或猜测素材 ID。
2. 插件中点击 **读取素材**，展开“手动粘贴完整引用 / 复用旧引用”，粘贴一个或多个引用，在每行左侧填写提示词中的原词，例如 `罗温`。手动粘贴的新素材不会自动填写关键词。若只保存手动引用，请清空上方自动读取行的原词。
3. 点击 **保存绑定**。只创建/更新当前方案的规则，不立即改网页；同名规则保留原颜色、排除项、启用状态和正则设置。新规则默认普通文本。
4. 点击 **预览全部替换**，查看范围、每条规则命中数量和示例，再确认执行。没命中的规则会标成 0 处；空替换文本会显示“删除文字”；只高亮词条不进入替换预览。
5. 在平台点击“预览提示词”，核对素材和编号，再决定是否保存。插件只发送正常编辑事件，不代点保存/生成；平台自身若有自动保存，编辑仍可能被自动保存。

复用方式：顶部 `⧉` 复制当前方案，保留颜色、规则、正则及排除项；双击方案名改名，下一集只改素材发生变化的规则。双击词条的“替换为”输入框可打开绑定面板；面板内也能复用其他方案已经保存的引用。

既有的文本导入导出同样支持完整引用，ID 始终作为字符串保留：

```text
罗温 - | [@罗温-作战服05#2100561479451070464]
```

## 安全范围与恢复

- 识别到西瓜创想的提示词编辑器时，单项/批量替换均只作用于当前可见提示词框，不修改左栏素材名称、菜单或其他分镜。
- 在其他网页使用素材引用规则时，必须先点击目标文本编辑框，否则拒绝整页替换。普通文本规则在未识别到平台编辑器时仍可替换页面正文，执行前预览会显示范围。
- 自动跳过已有 `[@名称#ID]` 引用和平台 `mention-chip` 标签，不修改标签内部文字；在同一次替换中，后续规则不会再次处理刚生成的内容。
- 若一个原词要改绑到另一素材，编辑规则只影响尚未绑定的原文。已绑定标签不会自动换版本，避免误改；需要先恢复原文或在平台手动移除原引用。
- 预览后正文/规则发生变化，会拒绝旧计划。先重新预览再执行。
- “恢复上次”恢复该次修改前的编辑器富文本，并发送编辑事件；如果之后又修改了正文或切换了内容，会拒绝覆盖新内容。最多保留当前页面最近10次记录，刷新/关闭网页后清空，不代替项目备份。
- 本地模拟验证了框架在 input 后重建引用标签的恢复流程；真实平台的保存、刷新持久化仍需在可丢弃分镜实测。插件不保证所有富文本编辑器会识别相同引用语法。
- 普通关键词按文本节点匹配，不能把隔在多个格式节点中的半个词当成一个完整关键词；已存在引用的跨节点片段会受到保护。

## 原有功能

一个 Chrome / Edge Manifest V3 扩展，支持：

- 多关键词同时高亮，每个词条独立颜色
- 页面变化后自动恢复高亮，不会因点击或滚动消失
- 支持普通 iframe、同源嵌入页面和开放式 Shadow DOM 内容
- 支持 `contenteditable` 富文本编辑器，不会为高亮而改写编辑器 DOM
- 支持按行批量导入，自动去重、自动分配颜色
- 每个词条可以独立启用正则表达式，替换时支持 `$1` 等捕获组引用
- 颜色修改立即保存；新增词条自动选择当前使用次数最少的颜色
- 词条列表独立滚动，“预览全部替换”始终固定在弹窗底部，小窗口也不需下滑整页
- 顶部方案标签支持多套匹配配置：单击切换、双击重命名、右键删除
- 在网页中选中文字后点击右键，可直接快速标注到当前方案
- 网页右键菜单可直接切换方案，或新建并切换到空方案
- 匹配项采用紧凑单行布局，单项替换按钮位于右侧
- 支持排除语法，例如 `祭坛 -悬崖祭坛` 会匹配“祭坛”但排除完整的“悬崖祭坛”
- “恢复上次”可以一键撤销最近一次单项或批量替换
- 替换成功后弹出规则明细和每条规则的实际替换次数
- 随时启用、停用、编辑或删除词条
- 区分大小写选项
- 单词条替换、全部词条批量替换
- 设置自动保存在浏览器本地

## 安装

1. Chrome 打开 `chrome://extensions`，Edge 打开 `edge://extensions`。
2. 开启“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择本文件夹 `persistent-multi-find`。

从旧版更新：保留原来的扩展安装，在扩展管理页点击该扩展的“重新加载”，然后刷新目标网页。不要先卸载，卸载可能清除原方案。所有旧方案继续使用。

安装后建议把扩展固定到工具栏。打开任意普通网页，点击图标添加关键词即可。
也可以按 `Ctrl+Shift+F`（macOS 为 `Control+Shift+F`）快速打开。

## 批量导入与正则

点击“导入 / 导出”后，文本框会立即显示当前方案的全部内容。可以直接编辑后重新导入，也可以点击“复制导出”。空行和完全重复的词条会自动忽略，颜色会自动循环分配。

也可以同时批量导入替换内容：

```text
文本1 | 替换文本2
文本2 | 替换文本2
```

再次导入已有匹配文本时，会更新其替换内容。点击“复制导出”可按同样格式导出当前方案。

没有排除项时也会保留一个空排除标记：

```text
文本1 - | 替换文本2
```

排除内容可以直接写在匹配文本后面：

```text
祭坛 -悬崖祭坛 | 神坛
```

这会替换普通“祭坛”，但不会高亮或替换“悬崖祭坛”中的“祭坛”。可以继续追加多个排除项，例如 `祭坛 -悬崖祭坛 -古老祭坛`。

每条匹配项右侧的“排”按钮可以打开排除编辑器，每行填写一个需要排除的完整文本。原来的逐项正则按钮已移除；批量导入时仍可通过“按正则表达式导入”统一设置正则模式。

勾选“按正则表达式导入”后，每一行按 JavaScript 正则处理。例如：

- `高级学生若.`：末尾匹配任意一个字符
- `玛丽莎-作...`：末尾匹配任意三个字符
- `黑月学院.*`：匹配以“黑月学院”开头的任意长度文字

替换字段支持正则捕获组，例如正则 `(塞拉)-(腿部包扎)` 可使用 `$1-$2` 作为替换内容。

## 注意

- 浏览器内部页面（例如 `chrome://` 和扩展商店）不允许扩展注入脚本。
- 替换会修改当前已加载的正文或编辑框，并通知编辑器；刷新后是否保留由网站的保存机制决定，不能依赖刷新来撤销。
- “恢复上次”最多保留当前页面最近 10 次替换记录；刷新页面后记录会清空。
- `contenteditable` 可编辑区域支持原生高亮；普通输入框和文本域支持替换，但浏览器暂不提供对其 value 文本进行多色 Range 高亮的接口。
